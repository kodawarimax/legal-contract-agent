# 契約書提出前 品質ゲートレビュー (`contract-quality-gate`)

契約書の修正案（`.docx` および解説書）を相手方に提出する前に、**過去の差し戻しパターン M1〜M16 と網羅性14点**を機械＋構造で審査します。

## 審査手順

1. **機械ゲート検査（CLI実行）**:
   ```bash
   python3 legal_contract_runner.py check-comments --comments-file comments.json
   ```
   - **M8**: 内部コード名（`G社`、`N社`、`○○氏` 等）の混入ゼロ
   - **M13**: 内部検討過程（「社内検討の結果」「当初案では」「交渉シミュレーション」「裁定を受けて」等）の混入ゼロ
   - **LEGAL**: 法的断定（「法的に問題ない」「このまま締結して差し支えありません」等）の混入ゼロ
2. **DOCX XML 構造検査**:
   - `word/document.xml` に削除（赤字 `#FF0000` ＋取消線 `w:strike`）と追加（青字 `#0000FF` ＋下線 `w:u`）が正しく出力され、共通部分が黒字で維持されているか（M2/M6/M11）
   - `word/comments.xml` の `@w:author` がすべて提出当事者名になっており、AI名義が混入していないか（M5）
3. **M15 / M16 構造点検**:
   - 号番号や項番号の欠番指摘はAIの誤読リスクがあるため「候補止まり（原本で実在確認するまで本文不変更）」としているか（M15）
   - 既存条文と目的・主体・手続・効果が異なる新設論点（PL保険義務等）を既存条文へ無理に相乗りさせず、独立条項として新設しているか（M16）
4. **人間目視ゲート（M9）**:
   - 最終提出前に必ず Word または Pages で開き、段落・空白・改行・フォント崩れを目視確認する。
