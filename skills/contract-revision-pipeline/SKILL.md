# 契約書修正スキル v3（M1〜M16実証統合・3段階パイプライン）

## 概要

相手方が作成した契約書を、依頼者の前提条件に基づいて修正し、
実務の交渉現場でそのまま相手方へ提出できる品質の修正候補（赤字取消線＋青字下線＋当事者名義Wordコメント）を**一回の操作で**生成し、人間・専門家の確認へ渡す。

## v3提出ゲート（必須）

1. **M1/M4**: 全コメントを相手の社内説明・締結・継続関係につながる提案にし、後半まで密度を落とさない。
2. **M2/M11**: 削除=赤字+赤取消線、追加=青字+青下線、理由=Wordコメント。両側の装飾を機械確認する。
3. **M3**: 前提条件・FB・根拠資料を確認する。未確認事項は「要確認」とする。
4. **M5**: `w:author` は提出当事者名。本文は自分=私/当社/弊社、相手=貴社/御社に固定する。
5. **M6/M7**: 最小編集を守り、甲乙、条・項・号、内部参照、存続条項を原文と突合する。
6. **M8**: G社/N社/○氏等の内部コード名を相手向けコメントへ出さない。
7. **M9**: 段落・空白・改行・フォントは機械検査だけで完了扱いにせず、提出前にWord/Pagesで人間目視する。
8. **M10**: 5STEP/プラン系は前回FBを全反映し、原体験まで掘り下げる。
9. **M12**: 再提出時だけ前版とコメント数・取消数・下線数を比較する。前版入力がなければ「未評価」と明記する。
10. **M13**: 当初案、社内検討、交渉シミュレーション、裁定等の内部過程を相手向けコメントへ漏らさない。
11. **M14**: 引用は手選別した一部でなく、全引用を原典と突合する。
12. **M15**: 欠番・欠落のAI検出は候補止まり。原本表示で確認するまで原文を変えない。
13. **M16**: 新設論点が既存条文と目的・主体・手続・効果を共有しない場合は独立条項とする。

本スキルは法的最終判断をしない。法令適用、条項の有効性、紛争、業法、競争法、知財、PL、個人情報、越境等は
「要確認」「要弁護士確認」と明示する。署名、外部送信、契約締結は人間ゲートに残す。

## ワークフロー（3段階パイプライン）

```
1. 原文契約書（DOCX/PDF/TXT）を読み込み
2. 前提条件を入力（ファイルまたはテキスト）
3. 【Stage 1】初期修正 (`build_stage1_revision_prompt`)
   - カテゴリ優先度付きで知識コーパス（knowledge/ 01〜08）を読み込み
   - 契約交渉メソッド + 14項目漏れチェックリストで初期修正案を生成
4. 【Stage 2】セルフレビュー (`build_stage2_self_review_prompt`)
   - 8項目＋14項目チェックリストで自己検証
   - 過剰修正・定義漏れ・主語逆転を修正
5. 【Stage 3】整合性チェック (`build_stage3_consistency_prompt`)
   - 残存条項リストの破壊的書き換え検出
   - 参照番号の誤修正検出
   - 原文に既にある条項の重複追加検出
   - 「別紙に定める」削除漏れ検出
   - 用語の首尾一貫性検証
   - 条文番号の連番ずれ検出
   - 価格拘束候補の検出（自動削除せず、事実確認・代替案・弁護士確認へ）
6. 戦略的コメント生成 (`generate_strategic_comments`)
   - 当事者目線（Bさんスタイル）のコメントを生成し、M8/M13/LEGAL違反を自動検閲・フォールバック置換
7. 赤入れDOCXを生成 (`generate_contract_review_docx`)
   - 原文ベース + 削除は赤取消線 + 追加は青下線 + 右側Wordコメント（w:author=当事者名）
```

## セルフレビュー・チェックリスト（8項目）

Stage 2 で必ず確認する：

1. **再販売価格の確認** — 価格拘束の有無・理由・取引実態を確認し、削除／希望価格＋販売店裁量等の候補を比較する。違法性は断定せず弁護士確認へ回す
2. **PLリスクの確認** — 製造・表示・販売の役割と事故リスクを確認し、製造物責任の分担・保険加入の要否を候補化する。無条件に追加せず弁護士・保険専門家確認へ回す
3. **本製品の定義** — 現行製品だけか将来製品も含めるか、案件の意図と一致しているか
4. **本製品の保証条件** — 製造・販売・顧客対応の役割と実際の保証方針に合う救済があるか。無条件に追加しない
5. **用語の首尾一貫性** — 「顧客」「本製品」等の定義語が統一されているか
6. **既存条項の重複禁止** — 原文にある条項を新規追加していないか
7. **最小限修正の原則** — 原案を無駄に書き直していないか
8. **独占販売権と更新方式** — 投資回収、試験運用、撤退可能性、交渉力を確認し、自動更新／合意更新／更新なしを比較する

## 修正ルール

### 絶対ルール
1. **原案をできるだけ生かしながら最小限の修正に留める**
2. 「ひっくり返すだけ」で済む修正は語順入れ替えのみ
3. 原文を全消去して書き直すのは絶対NG（相手の起案者への敬意を欠き交渉が停滞するため）
4. パッと見て結論がわかりやすい修正にする
5. 追加条項は原文の構造・文体に合わせて自然に挿入

### 素早い決断と用意周到さ（2026年判断原則）

- 契約交渉では、状況に応じた**素早い決断**と、決めた内容を実行可能にする**用意周到さ**をセットで扱う。
- 修正案は選択肢を並べて終わらせず、推奨案・判断期限・次に確認すべき実行条件を分けて示す。
- 仕事・費用・体制などの事情を一つずつ確認するが、相手を急かす圧力や法的断定には変えない。
- ゴールは締結だけでなく、続く関係に耐える着地である。

### 9つの判断習慣（2026年蒸留原則）

- **相棒の適性確認**: AI・専門家とも、得意・不得意を見極め、不得意な領域は人間ゲートで補う。
- **違和感を質問に変える**: 翻訳・修正を急がず、原文の意味が不明なら確認質問を先に置く。
- **課金条件を先に明示**: 無償範囲・有償範囲・課金タイミングを初期に分け、後出し請求を避ける。
- **異なる属性の協働**: 違いを消すのではなく、役割・用語・品質基準をすり合わせて協働を活かす。
- **小さな習慣で信頼を測る**: 返信期限、約束、連絡頻度など日常の反復行動を、相手との信頼性確認に使う。
- **複数見解を照合**: 行政・規制の確認では一人の説明を最終結論にせず、複数窓口と原典を照合し、人間が判断する。
- **重要語で立ち止まる**: 契約上の一語を読み飛ばさず、意味・法的効果・定義を確認する。
- **AIを相互監視させる**: 一つのAIの出力を別の検証ゲート（Stage 2/3 & M1〜M16）で照合し、最終決断は人間に残す。
- **素早い決断と用意周到さ**: 推奨案と判断期限を示し、実行条件を一つずつ確認して締結まで運ぶ。

## コメントルール（Bさんスタイル）

### 「誰が誰に」
- **書き手**: 修正案を提出する側の担当者（当社／弊社／私）
- **読み手**: 契約の相手方企業の担当者（貴社／御社）
- 法律家やAIが書いている体にしない
- 社内向け説明や交渉の裏側（当初案・妥協点・内部コード）を書かない

### 呼称
- コメント内では「甲」「乙」は絶対に使わない
- 自社 = 「当社」「弊社」（個人事業主なら「私」）
- 相手 = 「御社」「貴社」

### スタイル
1. 相手の立場・利益を長期的な目線で重視する
2. 双方の事情を率直に説明する
3. 「〜してみましたがいかがでしょうか？ご検討いただければ幸いです。」で締める
4. 法律用語（不平等、一方的に有利、違法、無効等）は使わない。状況を具体的に描写する
5. 1コメント2〜3文。簡潔に

### 模範例（Bさんのコメント）
```
当社の所在地が東京、御社の所在地が福岡ですので、
移動の時間／費用を考えるとどちらに決めても不満が残ります。
よって訴えられた当事者（＝被告）の住所/所在地を管轄する裁判所で
紛争解決をするという、両者平等な被告地主義の考えに基づいた
修正案にしてみましたがいかがでしょうか？
ご検討いただければ幸いです。
```
