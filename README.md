## 🎯 解決する課題

生成AIにそのまま「この契約書を自社有利に修正して」と頼むと、以下の**7つの致命的失敗**が頻発します：

1. **原案の全面書き換え（最小編集違反）**: 相手方の原案を無視して全文書き直し、相手担当者のメンツを潰して交渉を決裂させる。
2. **勝ちすぎ（何様条項）**: 法的に正しくても、相手の社内稟議が絶対に通らない一方的な条項を提案する。
3. **Word Track Changes（変更履歴）の表示崩れ**: 受領側のWord/Google Docsの表示設定によって変更箇所が見えなくなる。
4. **コメント名義（`w:author`）の事故**: Wordコメントの著者名が「AI名義」のまま相手方に送られてしまう。
5. **内部検討・コード名の漏洩（M8 / M13）**: 「社内検討の結果」「当初案から譲歩し」「G社・N社」といった内部事情が相手向けコメントに混入する。
6. **条番号繰り下げ・相互参照・存続条項のズレ**: 条文を1つ追加した結果、後半の「第○条に定める」や残存条項リストがすべて狂う。
7. **根拠なき法的断定（LEGAL違反）**: 個別の取引実態を確認せずに「法的に問題ない」「このまま締結できる」と断定してしまう。

本パッケージは、これらを**プロンプト頼みではなく決定論的Pythonエンジン＋構造化5席シミュレーション＋M1〜M16ランタイムゲート**で防止します。

| **4. 契約実務ナレッジコーパス（01〜08）** | `knowledge/01..08_*.md` | 契約交渉の基本原則、条項別チェックポイント、交渉心理学、よくある失敗パターン、NDA修正9ステップテンプレート、2026年講義・FB蒸留ルール集（50KB超）、決断と用意周到さの判断原則を匿名化・体系化して収録。 |

## 🚀 クイックスタート

### 1. インストール（Claude Code / Codex への登録）

```bash
git clone https://github.com/kodawarimax/legal-contract-agent.git
cd legal-contract-agent
pip install python-docx lxml pytest
bash install.sh
```

### 2. 3秒体験デモ（赤入れDOCX生成 ＋ v3ゲート検査）

```bash
python3 legal_contract_runner.py demo
```
`./output/sample_contract_redline_v3.docx`（赤取消線＋青下線＋当事者名義Wordコメント付き）と `./output/v3_gate_check_report.json` が生成されます。

### 3. 自分の契約書テキストから赤入れDOCXを生成する

```bash
python3 legal_contract_runner.py redline \
  --original original.txt \
  --revised revised.txt \
  --comments comments.json \
  --author "株式会社サンプル" \
  --output ./output/reviewed_contract.docx
```

### 4. コメントの v3 ゲート違反（M8 / M13 / LEGAL）を検査する

```bash
python3 legal_contract_runner.py check-comments --file comments.json
```

## 📋 網羅性14点チェックリスト ＆ v3提出ゲート（M1〜M16）

### 網羅性14点チェックリスト（全契約共通）
1. **参照条文の誤記**（「第○条に定める」と実体の整合）
2. **当事者（甲乙）の取り違え**（権利移転・義務主体の逆転）
3. **号番号・項番号の欠番／重複**（※M15: AI検出は候補止まりとし原本確認前に自動変更しない）
4. **条番号の重複**
5. **著作権・著作者人格権の扱い**（一括無償譲渡の回避・都度協議余地）
6. **残存（存続）条項リストの整合**
7. **遅延損害金の有無**（商事法定利率・年14.6%等）
8. **期限の利益の喪失**
9. **不可抗力からの金銭債務除外**（「金銭債務の支払義務を除き」）
10. **再委託の可否**（同等義務遵守＋連帯責任による条件付き認容）
11. **法律用語の誤字**（例: 相殺「対等額」→「対当額」）
12. **完全合意（統合）条項**
13. **条番号繰り下げの全追従**
14. **内部相互参照の更新**

### v3 提出ゲート（M1〜M16）
- **M1/M4**: 全コメントを相手の社内説明・締結・継続関係につながる提案にし、後半まで密度を落とさない。
- **M2/M11**: 削除=赤字+赤取消線、追加=青字+青下線、理由=Wordコメント。両側の装飾を機械確認する。
- **M3**: 前提条件・根拠資料を確認し、未確認事項は「要確認」とする。
- **M5**: `w:author` は提出当事者名。本文は自分=私/当社/弊社、相手=貴社/御社に固定する。
- **M6/M7**: 最小編集を守り、甲乙、条・項・号、内部参照、存続条項を原文と突合する。
- **M8**: `G社`/`N社`/`○氏` 等の内部コード名を相手向けコメントへ出さない。
- **M9**: 段落・空白・改行・フォントは機械検査に加え、提出前にWord/Pagesで人間目視する。
- **M10**: 事業計画/5STEP系は前回FBを全反映し、原体験まで掘り下げる。
- **M12**: 再提出時だけ前版とコメント数・取消数・下線数を比較する（前版なしは「未評価」）。
- **M13**: 当初案、社内検討、交渉シミュレーション、裁定等の内部過程を相手向けコメントへ漏らさない。
- **M14**: 引用は手選別した一部でなく、全引用を原典と突合する。
- **M15**: 欠番・欠落のAI検出は候補止まり。原本表示で確認するまで原文を変えない。
- **M16**: 新設論点が既存条文と目的・主体・手続・効果を共有しない場合は独立条項とする。

## ⚠️ 免責事項（Legal Boundary）

本ツールおよびエージェントは契約書の一次整理、確認質問、修正候補、交渉シミュレーション案の支援を行うものであり、**弁護士法上の法律事務や法的最終判断を提供するものではありません**。
法令適用、条項の有効性、紛争、業法、独占禁止法、知的財産権、製造物責任（PL）、個人情報保護・越境移転等については断定せず、必ず「要確認」「要弁護士確認」として扱い、最終的な契約締結・署名・外部送信は人間および実在の弁護士・専門家の判断のもとで行ってください。
