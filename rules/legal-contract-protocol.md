# 契約書修正・コメントプロトコル（v3 Unified）

B2B契約書レビュー・赤入れ修正時に遵守すべき標準規律。

## 1. 修正メソッド (MANDATORY)
- **削除**: 赤色文字（`#FF0000`）＋ 赤色の一本取り消し線
- **追加**: 青色文字（`#0000FF`）＋ 青色の一本下線
- **共通部分**: 黒字のまま維持（最小編集の原則）
- **修正理由コメント**: **Word コメント機能（吹き出し・右ペイン）採用**（`w:author` は必ず提出当事者名とし、AI名義は禁止）
- **Word の変更履歴機能 (Track Changes) は不使用**（受領側の表示設定で見え方が変わるため、本体テキストの色＋取消線/下線で表現）
- **納品標準**: ①修正前ファイル（原本） ②修正後ファイル（赤取消線＋青下線＋Wordコメント埋め込み `.docx`） ③修正コメント解説書（`.md`）の3点セット

## 2. 契約書 網羅性チェックリスト 14点 (MANDATORY)
すべての契約書修正で以下の14カテゴリを1件ずつ点検し、該当なしの場合も「該当なし」と明記して飛ばさない：
1. 参照条文の誤記 / 2. 当事者（甲乙）の取り違え / 3. 号番号・項番号の欠番・重複 / 4. 条番号の重複 / 5. 著作権・著作者人格権の扱い / 6. 残存（存続）条項リストの整合 / 7. 遅延損害金の有無 / 8. 期限の利益の喪失 / 9. 不可抗力からの金銭債務除外 / 10. 再委託の可否 / 11. 法律用語の誤字 / 12. 完全合意（統合）条項 / 13. 条番号繰り下げの全追従 / 14. 内部相互参照の更新

## 3. 提出前チェックシート v3（M1〜M16）
- **M1/M4**: 全コメントを相手の社内説明・締結・継続関係につながる提案にし、後半まで密度を落とさない。
- **M2/M11**: 削除=赤字+赤取消線、追加=青字+青下線、理由=Wordコメント。両側の装飾を機械確認する。
- **M3**: 前提条件・根拠資料を確認し、未確認事項は「要確認」とする。
- **M5**: `w:author` は提出当事者名。本文は自分=私/当社/弊社、相手=貴社/御社に固定する。
- **M6/M7**: 最小編集を守り、甲乙、条・項・号、内部参照、存続条項を原文と突合する。
- **M8**: `G社`/`N社`/`○氏` 等の内部コード名を相手向けコメントへ出さない。
- **M9**: 段落・空白・改行・フォントは機械検査に加え、提出前にWord/Pagesで人間目視する。
- **M10**: 事業計画/5STEP系は前回FBを全反映し、原体験まで掘り下げる。
- **M12**: 再提出時だけ前版とコメント数・取消数・下線数を比較する（前版なしは「未評価」）。
- **M13**: 当初案、社内検討、交渉シミュレーション、裁定等の内部過程を相手向けコメントへ漏らさない。
- **M14**: 引用は手選別した一部でなく、全引用を原典と突合する。
- **M15**: 欠番・欠落のAI検出は候補止まり。原本表示で確認するまで原文を変えない。
- **M16**: 新設論点が既存条文と目的・主体・手続・効果を共有しない場合は独立条項とする。
- **LEGAL**: 法令適用・有効性・競争法・PL等は断定せず「要確認」「要弁護士確認」と明示。「法的に問題ない」「このまま締結できる」と断定しない。
